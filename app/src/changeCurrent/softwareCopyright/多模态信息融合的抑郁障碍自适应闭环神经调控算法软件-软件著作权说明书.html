前言

概述

本文档对《多模态信息融合的抑郁障碍自适应闭环神经调控算法软件》的主要功能、系统结构、闭环运行流程和界面使用方式进行说明。本软件面向抑郁障碍干预场景，围绕“疗程前预检、动态电流执行、单次疗程报告和多疗程趋势复盘”构建完整的软件闭环。

产品简介

本软件是一套面向抑郁障碍干预场景的自适应闭环神经调控软件系统。系统以移动终端为操作载体，以刺激设备和多模态生理信息为输入输出对象，通过预检、执行、报告和趋势四类页面完成一个疗程从准备到复盘的完整组织。

与仅支持固定参数刺激的软件相比，本软件强调“多模态状态感知 + 自适应电流调节 + 疗程后反馈”的闭环思想。当前代码版本已完成页面导航、状态流驱动、设备实时信息展示和调节接口骨架，为后续接入 EEG、心率、皮电、动作信息及更复杂的融合模型提供稳定的软件基础。

体系结构

本软件采用分层架构设计，主要包括以下部分：

  1. 界面层：由 ChooseModeActivity、ChangeCurrentPrecheckBoardActivity、ChangeModeActivity、ChangeCurrentInsightReportActivity 和 ChangeCurrentTrendOverviewActivity 组成，负责页面展示、按钮操作和流程导航。
  2. 流程编排层：由 ChooseModeViewModel 和 ChangeModeViewModel 负责模式入口选择、调流状态维护、启动/停止控制和安全提示刷新。
  3. 设备通信层：由 BaseTesActivity、BaseTesViewModel、TesDeviceManagerService 和 TesDeviceManager 负责权限申请、前台服务、设备绑定、消息监听和指令发送。
  4. 算法接口层：以 CurrentAdjustAlgorithm 和 AdjustmentResult 作为当前版本的调流接口承载，同时为外部多模态融合模型、状态评估模型和闭环控制策略预留接入位置。

整体闭环流程

软件的整体闭环流程为：用户在模式选择页点击 changeCurrent 模式入口后进入疗程前预检页；预检通过后进入动态电流执行页；执行页根据设备反馈和算法决策进行调流，并在疗程结束后进入单次疗程报告页；随后可继续进入趋势总览页观察多疗程收敛情况；趋势页通过回到预检页的方式重新开启下一轮疗程，形成“疗程前 - 疗程中 - 疗程后 - 下一轮疗程”的闭环。

初始配置

软件在进入 changeCurrent 业务流程前，需要完成运行环境确认、权限申请和设备管理器初始化。

运行环境

本软件运行于 Android 设备，采用 Kotlin 开发。页面基类 BaseTesActivity 在初始化数据时统一触发权限申请和设备管理器初始化，保障不同模式页进入后的基础行为一致。

权限申请

软件会根据系统版本动态申请蓝牙扫描、蓝牙连接、蓝牙广播、前台服务、健康类前台服务、活动识别和人体传感器等权限。对于 Android 12 以下系统，则改为申请定位权限。用户应保证终端蓝牙可用，并完成权限授权，否则无法建立稳定的设备通信链路。

设备管理器初始化

基础 ViewModel 会通过 TesDeviceManagerService 启动前台服务并绑定 TesDeviceManager。该机制用于承载蓝牙连接、原始消息监听、解析后消息回调和设备状态同步。进入 changeCurrent 流程页后，设备状态、接收到的原始消息和解析后的设备信息均通过状态流展示在界面上。

模式入口准备

changeCurrent flavor 重写了模式选择页布局，仅保留“动态改变电流模式”入口卡片。共享的 ChooseModeActivity 与 ChooseModeViewModel 在点击该入口后，会通过类路径方式跳转至 ChangeCurrentPrecheckBoardActivity，从而进入本软件的专属闭环流程。

模式选择

设备准备就绪后，用户进入模式选择页并从中选择 changeCurrent 业务。

页面定位

模式选择页是本软件的业务入口。相较于主工程中的多模式选择逻辑，changeCurrent flavor 通过资源覆盖将页面聚焦为单一入口，减少操作复杂度，使软件更专注于自适应闭环神经调控流程。

页面组成

页面包含模式标题、功能简介和一张模式入口卡片。卡片中使用“Adaptive Current Flow”和“动态改变电流模式”两级标题，并明确标注“包含疗程前预检、执行流程、单次报告、趋势总览 4 个页面，仅实现 UI 和页面跳转”的说明文字，用于向操作者提示当前 flavor 的页面范围。

操作说明

  1. 进入模式选择页后确认当前仅显示一个业务模式入口。
  2. 点击“动态改变电流模式”卡片。
  3. 系统跳转至疗程前预检页，开始本轮闭环流程。

疗程前预检

疗程前预检页位于每轮疗程开始前，用于在进入动态调流前，对受试者状态、电极接触和目标电流窗进行人工复核。

模块定位

该页面承担“疗程前”阶段的人工确认与风险拦截作用。通过统一的预检页面，操作者可在开始刺激前完成电极接触、目标电流范围和当次疗程注意事项确认，降低误操作和执行前状态不一致带来的风险。

页面组成

页面由预检头图区、两张核心指标卡、本次疗程确认项区域和两个操作按钮组成。当前示例界面展示“电极接触 94%”“目标电流窗 0.8 - 1.4mA”等示例信息，并列出三条疗程确认项，用于体现页面结构和信息组织方式。

动态电流执行流程

动态电流执行页是本软件在“疗程中”阶段的核心模块，用于展示设备实时信息、驱动动态调流逻辑并组织疗程内页面跳转。

模块定位

本页面位于预检页和疗程后页面之间，是闭环执行中枢。它不仅负责启动和停止设备，还承担状态提示、算法占位、设备信息展示和疗程内导航等任务。

页面组成

页面由流程头图区、设备实时信息卡、流程状态卡和八个操作按钮组成。流程状态卡包括 processHint、readinessStatus、strategyStatus、stimulationStatus 和 safetyStatus 五个状态字段；设备信息区展示 deviceInfo 和 receiveMsg；底部按钮用于预检确认、策略刷新、开始/停止调流、跳转到预检页、报告页、趋势页和重置状态。

状态管理

ChangeModeViewModel 使用状态流维护页面状态。默认流程提示为“疗程前预检 - 动态电流执行 - 单次疗程报告 - 长周期趋势复盘”，默认状态依次显示“设备与电极：待确认”“调节策略：待下发”“动态电流：待启动”和“安全监测：等待设备连接与参数确认”。用户点击【标记预检完成】后，界面会更新为“设备、电极和受试者状态已确认”；点击【刷新调节策略（UI 占位）】后，界面会显示“缓升 - 维持 - 微调模板”等占位提示。

自适应调流逻辑

用户点击【开始动态电流】后，ViewModel 会以默认 30 分钟时长启动设备，并请求模式 TDCS_P、频率 0 的刺激参数。启动请求成功反馈到达后，ViewModel 会进入实时调节状态，并以 600ms 为周期执行一次调流逻辑。

实时调节通过 CurrentAdjustAlgorithm 接口输出三种结果：Increase、Decrease 和 Keep。当结果为增加电流时，系统调用设备管理器执行加流；当结果为减少电流时，调用减流；当结果为保持时，则继续等待下一轮调度。如果当前未注入真实算法，系统会将策略状态更新为“真实算法未接入，当前运行 UI 占位逻辑”，从而明确提示操作者当前版本的算法接入状态。

安全与异常处理

设备连接成功后，ViewModel 会主动执行握手并将安全状态更新为“连接已建立，等待刺激开始”；设备断开时，ViewModel 会停止周期调流，并将动态电流状态改为“已停止”，避免在连接异常时继续执行调流调度。用户点击【停止动态电流】后，系统会主动向设备发送停止指令，并将安全状态更新为“本次刺激已结束”。

页面跳转关系

执行页提供完整的疗程内导航能力：点击【返回疗程前预检】可回到预检页；点击【查看单次疗程报告】进入单次报告页；点击【查看趋势总览】进入趋势总览页；点击【重置页面状态】则恢复页面默认流程提示和默认状态文案。

下一阶段建议

当前示例页面给出“保持当前模板，但将高峰段目标电流上限从 1.4mA 收紧到 1.3mA”的建议，用于体现系统支持根据多疗程结果对后续策略进行收敛性优化。后续接入真实历史疗程结果后，可将该区域替换为基于多模态融合和趋势判断生成的真实建议文本。

多模态信息融合与自适应闭环机制

本软件面向多模态融合场景，闭环调控逻辑并不局限于单一电流参数，而是围绕多源生理信息、设备状态和疗程结果构建统一决策流程。

多模态输入来源

从软件架构角度看，多模态输入可包括 EEG 特征、心率变异性、皮电、运动状态以及设备上报的阻抗值、当前电流、剩余时间和电量信息。其中，设备运行信息已经能够通过 BaseTesViewModel 的消息解析链路实时更新到页面；其他生理模态可在后续版本中通过独立采集模块接入。

融合与决策接口

当前版本以 CurrentAdjustAlgorithm 作为策略决策的直接注入接口，并通过 AdjustmentResult 将融合后的调流结论抽象为增加、减少和保持三类结果。这样的接口设计使得多模态融合模型、状态评估模型和控制策略可以在算法侧独立演进，而不需要修改现有页面交互和设备调度框架。

闭环控制流程

  1. 疗程开始前在预检页完成电极接触、参数窗和受试者状态确认。
  2. 执行页启动刺激模式并等待设备返回启动成功反馈。
  3. 设备运行过程中持续上报当前模式、电流、剩余时间、阻抗值、设备状态和电量等信息。
  4. 算法层将多模态输入转换为调流策略，并通过 CurrentAdjustAlgorithm 输出决策结果。
  5. 设备层执行加流、减流或保持动作，并在下一轮周期继续收集反馈。
  6. 疗程结束后将单次结果与多次趋势映射到报告页和趋势页，形成对下一轮疗程的反向指导。

上述流程体现了“感知 - 评估 - 决策 - 执行 - 反馈 - 再优化”的软件闭环思想，是本软件技术方案的核心特征。

软件运行机制

本软件运行机制以“页面生命周期 + 状态流驱动 + 前台服务 + 设备回调”构成，确保闭环流程在工程实现上可观察、可扩展、可维护。

页面与 ViewModel 协作机制

各页面通过 BaseTesActivity 自动获得对应 ViewModel 实例，并在页面初始化阶段完成权限申请和设备管理器初始化。ChangeModeActivity 通过协程订阅 deviceInfo、receiveMsg 和 uiState 三类状态流，从而在设备信息变化或流程状态变化时自动刷新界面。

设备消息处理机制

BaseTesViewModel 统一监听原始字节消息和解析后的设备消息。原始消息会转换为十六进制字符串并显示在执行页上；上传反馈消息会被解析为当前模式、设定电流、设定时间、频率、剩余时间、阻抗值、当前电流、运行状态、停止标记和设备电量等字段，并汇总为设备信息文本显示给操作者。

连接与异常处理机制

当设备连接成功时，系统会主动执行握手同步设备状态；当设备异常断开时，ViewModel 会更新连接状态、停止调流调度并保留错误现场，便于排查问题。由于前台服务负责维护设备管理器实例，页面切换过程中仍可保持统一的通信基座。

可扩展机制

软件当前已将算法侧和页面侧解耦。后续若要接入新的多模态融合算法，只需实现新的策略模块并通过 setCurrentAdjustAlgorithm 注入到 ViewModel；若要增加新的疗程统计指标，则可直接复用现有报告页和趋势页的布局结构进行扩展，而无需重构基础导航链路。

常见问题说明

1. 为什么执行页会提示“真实算法未接入，当前运行 UI 占位逻辑”

这是当前版本的预期行为之一。执行页已经实现了设备启动、周期调度和调流接口骨架，但如果没有通过 setCurrentAdjustAlgorithm 注入具体算法实现，系统只会保留调度节奏并用占位文本提示算法尚未接入。

2. 为什么预检页、报告页和趋势页显示的是示例数据

当前版本的预检页、单次报告页和趋势页主要用于固化页面结构和闭环导航关系，因此电极接触率、目标命中率、趋势柱状图等内容仍以示例数据展示。后续接入真实采集结果和历史疗程数据后，可直接映射到现有页面结构中。

3. 为什么 changeCurrent 模式选择页只有一个入口

这是 flavor 级资源覆盖后的设计结果。changeCurrent flavor 覆盖了模式选择布局，仅保留“动态改变电流模式”入口，以便将本软件聚焦在自适应闭环神经调控业务上，减少与其他业务模式混用带来的干扰。

4. 设备断开后为什么动态电流会自动停止

当 ChangeModeViewModel 收到设备断开回调后，会立即调用停止调流逻辑并更新安全状态。这一处理用于避免在设备连接中断时继续执行电流调节，属于闭环控制中的安全保护措施。

5. 点击“回到预检重新开始”后为什么会直接返回预检页

趋势页使用了带 Intent.FLAG_ACTIVITY_CLEAR_TOP 的跳转方式，其目的是清理上层页面并返回到本轮疗程的起点，从而支持下一轮疗程重新执行。这一设计符合闭环流程中“复盘后再进入下一轮”的业务习惯。

6. 动态电流执行页显示哪些设备信息

执行页会显示当前模式、设定电流、设定时间、频率、剩余时间、阻抗值、当前电流、运行状态、停止标记和设备电量等信息，同时也会显示接收到的原始十六进制消息。上述信息有助于研发和实施人员观察调流过程和排查异常。
