# 《涉及多模态信息融合的抑郁障碍时空标记物挖掘算法软件》软件著作权说明文档

## 一、研发背景

抑郁障碍的临床评估长期依赖量表与访谈，主观性较强，难以稳定反映个体在不同干预阶段的神经生理变化。为提升评估客观性，本软件面向“脑电采集（EEG）+电刺激干预（TES/tDCS）+干预后复测对比”的数字化流程，构建可扩展的软件架构，实现如下目标：

1. 支持干预前 3 分钟脑波采集、30 分钟电流刺激、干预后 3 分钟脑波采集的标准化流程组织。
2. 支持对干预前后脑波及相关生理参数进行统一特征建模与差异对比。
3. 支持算法层与设备层解耦，便于后续接入不同脑电采集硬件和多模态融合模型。

本项目基于 Android + Kotlin 技术栈开发，已有蓝牙设备通信、设备状态上报、刺激模式控制等基础能力，并在此基础上新增“脑波前后测对比模式”的界面与接口层。

## 二、系统总体架构

系统采用“UI 层 - 模式编排层 - 设备通信层 - 算法接口层”的分层架构。

### 2.1 架构分层说明

1. UI 层：`Activity + XML` 实现用户交互与状态展示。
2. 模式编排层：`ViewModel` 负责流程状态机与接口调用。
3. 设备通信层：`BaseTesViewModel`、`TesDeviceManagerService` 处理蓝牙连接、指令发送、状态反馈。
4. 算法接口层：定义多模态融合与前后测对比接口，不与 UI 耦合。

### 2.2 关键流程

1. 用户在模式选择页进入“脑波前后测对比模式（3-30-3）”。
2. ViewModel 触发前测采集接口。
3. ViewModel 触发 30 分钟刺激接口。
4. ViewModel 触发后测采集接口。
5. ViewModel 触发前后测数据对比接口。
6. UI 持续展示每一步执行状态与设备上报信息。

### 2.3 架构示意（文字）

`ChooseModeActivity -> BiomarkerCompareModeActivity -> BiomarkerCompareModeViewModel -> BiomarkerModeGateway / MultiModalFusionAlgorithm / BrainWaveComparisonAlgorithm`

## 四、多模态生理信号数据融合算法

### 4.1 融合对象

融合数据来源包括但不限于：

1. 脑电时域与频域特征（如波段能量、节律稳定性）。
2. 刺激参数（刺激时长、设定电流、当前电流变化）。
3. 设备运行状态（阻抗值、剩余时间、电量等）。

### 4.2 融合流程

1. 对不同采样率与时间轴的数据做时间同步。
2. 对各通道进行去噪、标准化、缺失值修复。
3. 构造统一特征向量 `F = [F_eeg, F_stim, F_device]`。
4. 按权重或模型学习输出融合特征 `Z`，供前后测差异计算。

## 五、数据对比算法

### 5.1 对比目标

对比干预前后脑波及多模态融合特征，输出：

1. 变化方向（改善/无明显变化/恶化趋势）。
2. 变化幅度（差异分值）。
3. 关键时空标记物（通道、频段、时间窗）。

### 5.2 基本计算思路

可采用归一化差异评分：

`Score = Σ(w_i * (post_i - pre_i) / (|pre_i| + ε))`

其中 `w_i` 为特征权重，`ε` 用于防止分母为 0。根据阈值区间将结果映射到风险等级。

### 5.3 Kotlin 对比接口与示例实现

项目新增接口：

```kotlin
interface BrainWaveComparisonAlgorithm {
    fun compare(beforeFeatures: List<Double>, afterFeatures: List<Double>): Double
}
```

示例实现（用于说明算法接口落地方式）：

```kotlin
class WeightedDeltaComparisonAlgorithm(
    private val epsilon: Double = 1e-6
) : BrainWaveComparisonAlgorithm {

    override fun compare(beforeFeatures: List<Double>, afterFeatures: List<Double>): Double {
        val size = minOf(beforeFeatures.size, afterFeatures.size)
        if (size == 0) return 0.0
        val weight = 1.0 / size
        var score = 0.0
        for (i in 0 until size) {
            val pre = beforeFeatures[i]
            val post = afterFeatures[i]
            score += weight * ((post - pre) / (kotlin.math.abs(pre) + epsilon))
        }
        return score
    }
}
```

## 六、软件运行机制

### 6.1 运行入口

1. 启动应用后进入设备连接页。
2. 连接设备成功后进入模式选择页。
3. 进入“脑波前后测对比模式（3-30-3）”执行流程。

### 6.2 新模式流程状态驱动

`BiomarkerCompareModeViewModel` 通过状态流驱动 UI，步骤接口未接入时返回明确占位状态，示例如下：

```kotlin
fun requestBaselineCollection() {
    _uiState.value = _uiState.value.copy(
        baselineStatus = "前测脑波采集（${processConfig.baselineMinutes}min）：请求中..."
    )
    gateway?.collectBaselineEeg(processConfig.baselineMinutes) { result ->
        mainHandler.post {
            _uiState.value = _uiState.value.copy(
                baselineStatus = formatResult("前测脑波采集", result)
            )
        }
    } ?: markInterfacePending(StepType.BASELINE)
}
```

### 6.3 并发与线程模型

1. `StateFlow` 用于界面状态广播。
2. `Handler(Looper.getMainLooper())` 用于 UI 线程安全更新。
3. `viewModelScope + Dispatchers.Main` 用于消息回调和界面联动。

### 6.4 可扩展机制

1. 更换脑电采集 SDK：实现 `BiomarkerModeGateway` 即可。
2. 更换融合算法：实现 `MultiModalFusionAlgorithm` 即可。
3. 更换前后测对比方法：实现 `BrainWaveComparisonAlgorithm` 即可。
4. 不改 UI 层代码即可接入新算法版本，满足后续版本登记与迭代要求。

## 七、结论

本软件通过新增“3min 前测 + 30min 刺激 + 3min 后测 + 对比分析”的模式接口与流程 UI，完成了从设备控制到算法扩展的工程化骨架设计。在当前版本中，关键业务逻辑按需求采用接口占位，已具备后续接入真实多模态融合算法与时空标记物挖掘模型的实施条件，符合软件著作权技术说明文档对“系统结构清晰、功能边界明确、实现路径可复现”的描述要求。
